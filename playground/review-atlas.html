03a — equals and hashCode

Due 2026-11-16 · rung 1 · completed, shaky

A HashMap never searches: hashCode picks the bucket, equals picks the entry inside it.

Figure pending — being built in the background.
Reveal trap and answer

Trap

set.add(new Sku("A-1")); set.add(new Sku("A-1"));  // ❌ size 2 — equals without hashCode
@Override public int hashCode() { return code.hashCode(); }  // ✅ same fields as equals

Interview

  1. Equal objects ⇒ equal hash codes; equal hashes do not imply equal objects.
  2. Override both or neither: equals alone gives duplicates and null from get.
  3. A key's hash must not change while it is in the map — the entry is never re-filed.

04b — Composition over inheritance

Due 2026-11-16 · rung 1 · completed, shaky

Inheritance ties you to how the parent is implemented; composition ties you only to what it promises.

Figure pending — being built in the background.
Reveal trap and answer

Trap

public final List<Item> items = new ArrayList<>();   // ❌ final freezes the reference, not the list

Interview

08a — List and Set

Reveal trap and answer

Trap

Interview

16 — SQL fundamentals

Due 2026-11-16 · rung 1 · scratched

SQL runs FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY, and NULL compared to anything is UNKNOWN.

Figure pending — being built in the background.
Reveal trap and answer

Trap

WHERE Id NOT IN (SELECT ManagerId FROM Emp)    -- ❌ one NULL → empty result
WHERE NOT EXISTS (SELECT 1 FROM Emp m WHERE m.ManagerId = e.Id)  -- ✅

Interview

  1. Logical order: FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY.

44 — Schema design and DDL

Due 2026-11-16 · rung 1 · scratched

Reveal trap and answer

Interview

45 — Advanced SQL: window functions

Due 2026-11-16 · rung 1 · scratched

A window function computes a value per row from related rows without collapsing them; the ranking functions differ only on ties.

Figure pending — being built in the background.
Reveal trap and answer

Trap

09a — Comparable vs Comparator

Due 2026-11-16 · rung 1 · completed, shaky

Comparable is one natural order inside the class; Comparator is any number of orders outside it.

Open figure full size
Reveal trap and answer

Trap

new TreeSet<>(comparingInt(String::length))                 // ❌ "pea" dropped — same length as "fig"

Interview

  1. Comparable: one natural order, compareTo(other), one argument because this is the other side.

10a — Lambdas, functional interfaces, method references

Interview

08b — Maps

Due 2026-11-16 · rung 3 · completed, ok

The backing structure decides order, cost and null.

Figure not built yet — added by the next scratch review that re-reads this topic.
Reveal trap and answer

Trap

Map<String,Integer> t = new TreeMap<>(String.CASE_INSENSITIVE_ORDER);

Interview

01 — Types, values and references

Due 2026-11-16 · rung 7 · completed, solid

A variable never holds an object — it holds a primitive value or an object's address.

Figure not built yet — added by the next scratch review that re-reads this topic.
Reveal trap and answer

Trap

Integer c = 128, d = 128;  c == d    // ❌ false — two objects; equals

Interview

  2. unmodifiableList is a live view; List.copyOf a frozen snapshot.
  3. new ArrayList<>(x) is shallow — elements still shared.
